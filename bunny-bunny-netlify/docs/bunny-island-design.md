# Bunny Bunny · 兔屿生活 3D 游戏设计

> 本文件按 2026-09-27 的用户需求更新。早期 `ai-phone-spec.md` 5.11 写的是 2D 俯视小屋；现在以用户新要求的可爱 3D 小岛为准。规则由代码判定，模型负责角色语言和有边界的自主意图。

## 1. 游戏定位与生活循环

「兔屿生活」是手机里的一个持续存在的小世界。用户装扮自己，走进家园、小岛与好友家里；现实时间推动作物、天气、访客和节日。角色不会等在原地只响应按钮：他们有日程、性格、自己的房子、关系及动机，会预约、来访、帮忙、带走或留下新的故事。它和聊天 App 属于同一个世界，不重新创造平行人格。

核心循环：**看到今天的岛 → 走动 / 摆放 / 照料 → 角色注意到可见动作并作出回应 → 世界状态与关系记忆更新 → 离线时间继续流动 → 下次回来发现细节变化**。每个动作应有明确的反馈，不能把用户没做过的事写成事实。

基调是有一点笨拙的温柔：种歪的萝卜、替你浇了半块地的邻居、在客厅里绕不过椅子的宠物，都可以成为日记和聊天里的小事。角色不应每次都夸赞用户；允许赶时间、没话说、拒绝帮助或稍后回消息。

## 2. 空间与镜头

- 3D 风格：低多边形、软糖色、圆润比例、短阴影、可读的大形状；默认正交斜视镜头，保留旋转与缩放。
- 地图层级：群岛总览 → 自己的小岛 → 家外庭院 → 室内房间 → 好友岛。室内外无损切换；手机小屏优先保持清晰可点的目标。
- 基础网格：一格是一个放置单元，摆件与农田可占多格；坐标、朝向、碰撞、归属权都写在数据里。镜头不决定规则位置。
- 性能：首屏静态几何与角色模型先渲染，纹理及装饰后到；低端设备可降分辨率、关粒子与动态阴影；支持 reduced motion。游戏暂停在后台，但农作物依据时间戳离线生长。
- 素材管线：先用内建低模几何和调色板，后续支持 glTF/GLB 模型、贴图包、动作片段。导入资产必须有尺寸、碰撞盒、锚点、交互标签和手机端面数预算。

## 3. 人物与装扮

用户角色可编辑肤色、发型/发色、眼睛、脸型、上衣、裤装、鞋、配饰、表情与昵称；界面要有实时预览、撤销、套装收藏、随机搭配。改变外观不会擦除关系记忆。CHAR/NPC 的初始外观由人设、已有资料和世界书推导，用户可以授权「让 TA 自己决定」；角色对自己换装有原因，例如季节、工作、约会或个人喜好。每次自主改动留事件，允许恢复。

动画状态至少包括 idle、walk、talk、care、fish、sit、gift、sleep。对话框挂在角色头顶附近，遮挡时移到屏幕安全区，并可展开完整聊天。动作先由代码执行并确认，再交模型描述可见事实；模型不能凭文本直接移动或修改库存。

## 4. 家园、种植、宠物与钓鱼

**家园**：房间和庭院支持家具摆放、旋转、染色、分层、收藏蓝图；墙地板和灯光单独编辑。家具定义功能标签，床能睡、桌能放东西，不能只是一张图。访客的通行范围及互动许可由用户设置。

**农田**：翻地 → 播种 → 浇水 → 生长 → 收获。每株作物保存 `plantedAt`、`wateredAt`、品种、土地与操作者；阶段由真实时间计算，不依赖页面一直打开。季节、天气、浇水和 CHAR 帮忙改变生长速度，但不会倒流。收获由规则表算数量与品质，模型只写见闻。

**宠物**：每只宠物有名字、物种、外观、饱腹、心情、健康、亲密度、习惯与休息点。照料是有时间成本的动作；代照料需要用户给权限，且有库存与日程门槛。角色可能喜欢、害怕或与某只宠物亲近，这些都可成为事件。

**钓鱼**：天气、时间、季节、地块决定鱼池，代码掷种子决定上钩种类，点击/按住小游戏决定是否钓起。角色可以围观、建议或一起钓；不能由模型直接宣布获得稀有鱼。

## 5. 角色自主生活与访问

每个角色有自己的岛、住宅、装扮、库存摘要、可访问日程、访问权限和当前意图。角色自己决定是否邀请用户、来访、浇水、喂宠物、送礼或离开；调度器必须校验日程、关系、距离、天气、当前状态及频率上限。来访事件明确分成 **提议、用户许可、执行、结果**。没有权限时只会询问，不会擅自改用户家园。去 CHAR 家时也受 TA 的邀请及时间限制。

现场聊天读到用户刚做的动作、角色当前可见范围、双方关系、各自私有记忆和共同见闻。超出视线或离线的角色不会知道即时动作；之后可以通过消息、目击者或用户告知而知道。角色台词有停顿、误解和话题延续，不要输出任务日志口吻，也不要每两步都插一句。

## 6. 剧情与真实世界关系网

剧情不是无限制地让模型「生成故事」，而是事件卡：触发条件、参与者、地点、前置事实、可选行动、冷却、后果、可见对象。模型只在卡片容许的边界内写对话、细节和角色意图。家具、天气、种植收成、角色约定和正在发生的群聊都可以触发卡。没有触发条件时可以安静生活。

共享真相存入世界事件 `worldLog`，带 `actorIds`、`witnessIds`、地点、时间、来源和 `public`。每位 CHAR/NPC 的记忆库仍独立：亲眼看到的岛上动作写到目击者各自记忆；群聊与单聊通过同一人物和账号对应的 `memoryOwnerId` 检索；关系图为人物对人物的边，双方对同一事件可以有不同解释。角色不可读取其他人的私人日记、私聊或隐藏事件。用户纠正事实时保留修订链，并让后续推理以新事实为准。

例子：用户在阿岚面前种了一排草莓，阿岚目击且记住；小鱼不在场，不知道。阿岚后来在群里说「那排草莓」，群成员因此获得一条由阿岚转述的**间接**见闻，可信度低于亲眼所见。阿岚晚上私聊用户时能自然提起浇水；其他成员不会突然说自己亲眼看过。

## 7. 数据和 AI 契约

`islandState` 按世界与账号隔离：`schemaVersion`、`worldId`、`accountId`、`homeId`、`avatar`、`tiles`、`objects`、`crops`、`pets`、`visits`、`actionLog`、`sceneRevision`。物品、货币及关系调用现有系统作为唯一来源，避免双份库存。模型收到最小必要上下文，不接收整个存档。事件采用可重放 ID，刷新页面不会重复收获、重复赠礼或重复写记忆。

现场 AI 输入示意：`{actorId, location, visibleActions:[{id,kind,actorId,targetId,at}], visiblePeople, sharedFacts, actorPrivateMemory, mood, schedule}`。输出只接受 `{"speech":"...","emotion":"...","intent":"idle|look|visit|help|leave"}`，并经校验、冷却与权限检查。网络失败时动作仍完成，台词显示自然的本地反馈及可重试入口；绝不伪称模型已回复。

提示词核心：以角色本人说话，不用旁白、不替用户说话；知道什么由目击和公开传播决定；只提与眼前动作有关的一两个细节；口吻可随情绪及关系变化，允许短句、沉默、反问和转移话题；不要「作为 AI」「很高兴」「让我们一起」等格式化套话。私有记忆不能在多人场合默认公开。

## 8. 阶段计划与验收

### 第一步：可进入的 3D 岛（本轮）

- 游戏 App 入口进入「兔屿生活」；使用本地 WebGL 几何呈现可旋转的 3D 岛、用户与一位角色、房屋、树木、农田和海面。
- 点击场景移动；可选择外观颜色并持久化；可在田地播种，作物随真实时间变大；角色根据用户可见动作说现场对话，有已配置 API 时可调用模型，没有时清楚显示待配置状态。
- 每次可见行为落入事件日志，只写入确实在场的角色的私人记忆；返回后保持位置和作物状态。
- 验收：离线打开能看到岛并移动；刷新后头像配色与农田保留；未配置 API 不捏造 AI 台词；不在场角色不收到目击记忆。

### 第二步：家与装扮

可捏脸和完整换装、家具拖放与碰撞、室内外切换、家园蓝图与撤销；角色初始形象由人设推导并可自主换装。验收包括两个世界和两个账号互不串档。

### 第三步：生活职业

完整种植品种、浇水、收获与库存；宠物领养/照料；钓鱼、商店和节日天气。补算有确定性的上限，断网重开结果一致。

### 第四步：互访与关系剧情

CHAR 家园、邀请/来访/访问权限、照料委托、角色自主行动、剧情事件卡、群聊和单聊的事件回流。重点验收是谁亲眼看见、谁后来听说、谁依然不知道。

### 第五步：美术和长期运营

正式可爱 3D 模型与动作、用户导入、摄影模式、岛屿分享、无障碍与移动性能调优。用户数据可导出，付费和联机玩法待单独设计，不作为模拟真人体验的前提。
