# 社交媒体、聊天皮肤与真实摄像头更新

## 使用方式

- 新存档从空白开始。在相识簿填写自己的称呼和世界名称，再创建角色。没有内置 USER、CHAR、NPC、世界书、预设或聊天记录。旧存档首次启动会清理可识别的示例实体和关联内容；自建人物及 API 配置保留。
- 回声广场、瞬语、映兔的发布和评论入口都提供 emoji、表情包、相册、图片直链与生图工具。图片写入本机 IndexedDB。论坛与瞬语最多四张；映兔发布主素材为一张图片或一个视频，评论最多四张。
- 三个平台各自的设置中都有「本平台图片生成」。还需要在「模型与 API」配置并打开全局生图。手动点击「✧ 生图」输入画面；自动刷新时，如果文本模型提供 imagePrompt，每批最多生成一张配图。失败保留文字并提示错误。
- 回声广场点击帖子进入完整详情视图；回复支持图片、表情包和多层评论。图片点击放大。
- 瞬语头像打开账号菜单。个人页包含贴文、回复、媒体，以及仅自己可查看的喜欢、书签；可查看关注关系、置顶帖子、向站内私信或兔信分享。
- 心声提示读完即消失。聊天「＋ → 心声 → 心声匣」查看这段聊天历次心声；不会放入记忆库，也不再按八十条截断。
- 聊天设置打开「真实摄像头」。进入视频通话后点小画面上的「摄像头」授权，点 ↻ 切换前后镜头；再次点击摄像头或离开通话会停止采集。
- 另行打开「摄像头动作识别」后，首次会下载 MediaPipe 手部和面部模型。处理在浏览器 Worker 中运行，摄像头图像不发送给聊天 API，只发送稳定动作的文字观察。微笑、嘟嘴采用面部形态特征；手指比心、贴脸比心、双手比心、头顶比心、捂嘴、撇嘴属于实验性几何候选，点击候选确认后才发送。不会推断情绪或心理。

## 验证与限制

### 游乐屋和小组滑动

游乐屋现在先展示游戏列表。兔屿生活、翻翻心事（六对翻牌）和三步之间（井字棋）均有完整详情、每日任务和开始入口。任务按当前世界的时区日期更新，同一天保留进度；岛上任务记录走路、种植或照料、换装等真实操作。两个轻游戏可离线游玩，不依赖文本 API。不同世界和 USER 的进度分开保存。

回声广场小组列表支持触屏横滑、鼠标拖动，以及聚焦后的左右方向键。卡片拖动和系统右滑返回隔离。

本轮追加参考图校准了 iMessage 的头像和玻璃名称栏、LINE 的蓝色顶栏与白色输入栏、KakaoTalk 的顶栏工具胶囊和浅蓝输入栏。三个皮肤使用 SVG 连续轮廓连接气泡和尾巴；原生和微信的气泡轮廓未改。气泡大小、圆角和用户 CSS 仍然生效。

- `node --test tests/social-camera.test.mjs`：空白种子、示例迁移、图片评论、生图开关隔离、识别稳定与去重。
- Edge 浏览器实测：空白建档、论坛发帖与回复、三个应用图片发送、X 分类与菜单、聊天 SVG 与 reaction 位置。
- MediaPipe 两个模型已在真实浏览器加载，空白帧推理返回无动作。通过模拟摄像头流验证请求、镜头切换与停止轨道。
- 生图使用模拟 API 返回测试，没有使用私人 API Key 进行收费调用。
- 未做真人手机摄像头动作准确率测评。遮挡、光照、取景和设备性能会影响识别；所有比心候选需要用户确认。前后切换使用 facingMode，单摄像头设备可能仍返回同一镜头。需要 HTTPS；模型下载失败可重试，普通摄像头画面仍可使用。
- 此更新强化 X 常用社交流程与视觉布局，不包含真实 X 的登录、支付、广告或服务器推荐服务。

模型接口参考：[Google Hand Landmarker](https://developers.google.com/edge/mediapipe/solutions/vision/hand_landmarker/web_js)、[Face Landmarker](https://developers.google.com/edge/mediapipe/solutions/vision/face_landmarker/web_js)。
