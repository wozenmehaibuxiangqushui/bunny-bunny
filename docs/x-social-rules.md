# X 社交模块

本版是本机模拟社交客户端，不连接真实 X，不自动冒充角色生成内容。

## 已实现

首页、关注流、搜索、话题榜、贴文详情与回复、图片、转发/引用、点赞、书签、个人主页、关注、通知、私信、账号切换、日夜主题。数据随现有 store 保存；照片进入 IndexedDB。趋势来自本世界观已有贴文，浏览量按不同账号计数，不伪造人气。

用户账号分别拥有资料、关注、私信和书签。角色与 NPC 的公开内容限制在所属世界观；关注者可见内容另外校验关注关系。小号未向角色披露前，角色上下文没有主账号身份字段。独立身份始终按独立的人处理。

## 下一阶段 AI 接入约定

`js/x-model.js` 的 `buildXRoleContext` 生成角色公开上下文，尚未接入自动生成调用。接入时必须在服务响应落库前再次校验角色、世界观、可见贴文 ID、动作类型与频率；不能仅依靠提示词保证隔离。

角色公开发帖应结合人设、职业、行程和允许公开的近期经历；私聊、私密记忆和未披露身份不直接放进公开上下文。绑定 NPC 只能获得其关系和世界观允许获知的内容。好友关系不自动等于社交平台关注关系。

记忆条目应记录 sourcePostId、作者账号、可见范围、可信度、是否本人陈述。未识别小号的互动归入独立账号下的普通公开经历；披露后建立身份关联，不能倒写成角色过去一直知道。删除贴文应撤销后续可检索来源；角色已经读过的事件只保留“曾看见、后来删除”的事实，不当作仍公开的材料。

名声建议分成知名度、好感、专业可信度、争议度；按世界观和受众圈层分别计算，限幅且随时间衰减。用户编辑的“名人”属于人设，不能凭空制造互动量。名声不直接改变亲密关系中的好感；负面评论也不能自动当作事实。

可以增加的玩法：亲友圈与公开圈、匿名小号试探、职业账号营业与私人账号碎碎念、共同话题活动、辟谣与更正、私密收藏夹、长贴串、角色互相引用。优先实现圈层和长贴串，再加入有来源、可关闭的角色自动互动。

## 验证

在 `bunny-bunny-netlify` 目录运行 `python -m http.server 8000`，打开 `http://localhost:8000/`。仓库根目录运行 `node --experimental-vm-modules tests/interaction-model.test.mjs` 验证拖拽与社交隔离规则。
