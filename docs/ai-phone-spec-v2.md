# AI 陪伴「小手机」项目规格书（给 Codex 的实现文档）

## 0. 给实现者的说明

- **目标**：纯前端 HTML+JS（无后端）、移动端优先的 AI 陪伴 / 角色扮演「小手机」。
- **商业形态**：买断制。API Key 与所有素材（立绘、头像、表情包、音色、音乐、视频）均由用户自备，项目**不内置任何第三方版权素材**，只提供占位素材（emoji / CSS / SVG）和导入入口。
- **工作方式**：严格分阶段实现（见第 8 章）。每个阶段结束必须「可运行、可存档、可导出」。不要一次性写完全部，先做地基：存储层 → LLM 网关 → 世界引擎 → 聊天。
- **技术约束**：
  - ES Modules，可不依赖构建工具运行（可选 Vite）。
  - IndexedDB 存主数据，localStorage 只放小配置。
  - PWA（manifest + service worker），可添加到主屏、离线可开。
  - 所有数据一键导出 / 导入 JSON，多存档槽位。
  - 375–430px 宽度优先，适配安全区。
- **代码原则**：UI 与逻辑分离；每个 App 是独立模块，通过统一的 EventBus 和 Store 通信；**UI 层禁止直接调用 LLM，一律走 LLM 网关**。
- **核心设计哲学**：**代码负责「决定」，LLM 只负责「表达」。** 概率、日程、数值、规则、状态机、谁发言、发不发，全由代码算；LLM 只根据结构化上下文写台词和文案。

```
  /llm      gateway  prompts/  schemas/  validators/

```

分层：Data → Engine（确定性代码）→ LLM Gateway（表达）→ UI Apps。

## 2. LLM 网关与「确定性」保障

### 2.1 接入
- 以 OpenAI 兼容格式为主（base_url + key + model），预留 Claude / Gemini 适配器。
- 设置页提供「测试连接」；Key 仅存本地，可选加密（用户口令）。
- 支持流式输出；支持多个 API 配置档（聊天用一个，摘要/生成类用便宜的模型）。

### 2.2 调用类型（每类独立模板 + 输出 schema + 温度）

| task | 输出 | temperature |
|---|---|---|
| chat_reply | JSON（消息数组 + state_delta） | 0.8–1.0 |
| group_reply | JSON（多角色发言序列） | 0.9 |
| schedule_gen | JSON（日程块） | 0.5 |
| catchup_world | JSON（世界日志） | 0.7 |
| memory_summarize | JSON（记忆条目） | 0.3 |
| content_gen（动态/论坛/查手机内容） | JSON | 0.9 |
| game_master | JSON | 0.5 |

### 2.3 Prompt 分层顺序（自上而下）
1. **A 功能协议**（项目写死，用户不可改、不可覆盖）
2. B 世界书命中条目
3. C 角色卡
4. D 用户人设
5. E 记忆检索结果
6. F 当前状态快照（当前时间 / 日程状态 / 情绪 / 关系值 / 近期世界日志）
7. G 近期对话
8. **H 本次任务指令 + 输出格式**（放在最后，权重最高，不可覆盖）

用户自定义预设只能插入 B–D 层。

### 2.4 输出协议示例（chat_reply）
```json
{
  "messages": [
    {"type": "text", "content": "刚下班，累死了"},
    {"type": "sticker", "id": "tired_cat"},
    {"type": "text", "content": "你吃了没"}
  ],
  "state_delta": {
    "mood": {"tired": 0.2},
    "affinity": 1,
    "commitments": [{"what": "周六一起看电影", "when": "2026-09-26T19:00"}],
    "memory_hints": ["用户今天加班"]
  },
  "wait": {"nextMessageInMin": 0}
}
```
所有可执行动作（sticker / 红包 / 转账 / 位置 / 撤回 / 语音 / 通话请求）必须是**枚举 type**，代码解析执行。

### 2.5 校验与重试
1. 解析 JSON（容错：去 markdown 围栏、修复尾逗号、提取首个 `{}`）。
2. Schema 校验。
3. 业务校验：sticker id 是否存在；红包/转账金额是否在余额内；是否替 user 发言；长度是否合理；是否出戏。
4. 失败 → 把错误信息附在下一次请求里重试，最多 2 次。
5. 仍失败 → 降级为「标签文本模式」（如 `<msg>…</msg>`）解析。
6. 再失败 → 拟真兜底（如「对方好像走神了…」）+ 重试按钮。

### 2.6 模型能力档位
设置里选「强 / 中 / 弱」。弱档：更短的 prompt、更简单的 schema、拆分成多个小调用、更多少样本示例、关闭复杂功能（如群聊多角色一次生成）。

### 2.7 真人感规则（写进 A 层 + 代码后处理）
- 一次回复拆成 1–5 条短消息；代码按字数模拟打字延迟，显示「正在输入…」，可中途消失再出现（犹豫感）。
- 口语化。禁止：总结式收尾、「有什么可以帮你」、客服腔、每条都反问、无意义的省略号堆叠。
- 不必回应每一句；允许岔开话题、忽略、已读不回。**是否回复由代码根据日程 availability 决定，不交给 LLM。**
- 情绪有惯性：mood 值由代码维护（事件缓慢改变），LLM 只读取。
- 防复读：与最近 10 条自己的消息做字符 n-gram 相似度检测（Jaccard > 0.6 则重生成）。
- 严禁替 user 说话或替 user 做决定；严禁出戏（除非用户在设置中开启）。
- 每个 char 有「说话指纹」：口头禅、标点习惯、常用语气词、消息长度分布，写入角色卡并进入 prompt。

### 2.8 上下文预算
估算 token；最近对话窗口 + 记忆 top-k + 世界书命中，超预算按优先级裁剪。A、H 层永不裁剪。

### 2.9 调试面板
可查看每次调用的完整 prompt、原始输出、校验结果、重试次数、耗时、token 估算。（开发与售后利器）

### 2.10 回归测试
`/tests/fixtures` 存典型输入 → 期望结构；提供脚本批量跑不同模型，输出通过率报告。

## 3. 世界引擎（角色拥有自己的时间线）

### 3.1 数据边界与事实来源
- 每个世界独立保存 Entity、ScheduleDay、RelationEdge、WorldEvent、WorldLog、DeliveryJob。主键必须带 worldId；与 USER 有关的可见性和消息再加 accountId。CHAR 与 NPC 共用实体规则，USER 的输入是外部事件，不会自动成为所有角色已知事实。
- WorldLog 是不可变事实流水：id、worldId、occurredAt、actorIds、witnessIds、place、kind、payload、source、revision。UI、记忆、动态、通知都是它的投影。更正写新版本并保留来源，不静默改写旧事实。
- 代码先计算事件是否发生、谁参与、何时送达以及状态变化；模型只为已批准的事件写描述。模型不能追加参与者、篡改时间、钱、关系值或替 USER 发言。

### 3.2 日程与可用度
- 日程键为 worldId + entityId + 本地日期 + 时区；首次生成后固定。seed 由这些字段和规则版本计算，离线重算得到相同骨架。每个 block 含起止时间、地点、活动、availability、可接电话、来源与优先级。
- 冲突优先级：用户锁定事件 > 双方已确认约定 > 固定日程 > 临时事件 > 作息模板 > 随机填充。半开区间避免相邻时段重叠；跨午夜拆成两天；时区或夏令时变化时以绝对时间存储，再生成当地显示。
- 聊天识别出的约定先成为 proposal；双方确认且时间可用后由代码提交。提交以 commitmentId 去重，更新受影响日期的日程投影，不重掷其他事件。拒绝、改期、取消均写事件流水。
- availability 驱动发送/已读/回复延迟、主动消息和通话；角色状态按当前 block 推导。UI 只展示角色愿意公开的状态，隐藏完整私有日程与精确位置。

### 3.3 离线补算与投递
- 每个世界记录 lastTickAt 与规则版本。启动、回到前台或手动刷新时补算，按最多 6 小时切片；一次最多处理 72 小时，更久合并为摘要。相同 worldId + 时间片 + 规则版本的 jobId 必须幂等。
- 代码用日程交集、关系边、事件权重和世界活跃度抽取候选。先写确定性事件骨架，再批量请求一次模型文案；失败时保留骨架，用本地模板呈现，绝不重复扣款或重发通知。
- 待发消息在骨架阶段确定 sender、recipientAccountId、dueAt、可见见证人和去重键。前台恢复后按 dueAt 顺序投递；飞行模式、勿扰、离线与锁屏只改变传输/提醒，不倒改事件发生时间。补算成本与通知数量都有上限。

### 3.4 关系、知识与事件池
- RelationEdge 以无序实体对唯一索引，含双向可不同的 affinity、信任、熟悉度与历史；每次变化有原因事件、上下限和冷却时间，不允许一次模型回复任意跳数值。
- 知识按 witnessIds、被告知事件、公开内容逐步传播。构建每位说话者的上下文时只取其可知事实；群聊、论坛和小号同样遵守知识边界。
- 事件池使用版本化 JSON，trigger、权重、互斥组、冷却、effects 和文案提示分别校验。世界书只添加候选与表达素材，不能绕过概率、知识或日程规则。
- 现实时间、天气、日历与位置均为用户可关闭的输入；权限关闭后沿用虚构世界设定，不推断真实住址。

### 3.5 验收
同一天重复进入日程一致；离线补算执行两次不会重复事件或通知；冲突约定不会覆盖锁定日程；未见证事件不会进入角色提示词；无模型或断网时世界仍可继续。

## 4. 记忆系统

### 4.1 所有权与层次
- 记忆主键至少含 worldId、accountId、entityId。大小号与平行世界默认隔离；群聊只给实际在场且可知的角色写入。跨身份共享必须由显式剧情事件授权并保留审计记录。
- working 是最近原始消息窗口；episodic 是带发生时间、来源消息 ID、参与者和可信度的事件；semantic 是长期事实与偏好；milestone 是用户或规则确认的关系里程碑。心声是按需生成的文学内容，不等于模型推理，也不自动写成事实记忆。
- 每条记忆保存 id、kind、text、sourceIds、createdAt、lastSeenAt、importance、confidence、visibility、status、revision。用户纠正记忆时以新版本覆盖检索结果，不销毁来源。

### 4.2 写入与冲突处理
- 每 N 轮、会话结束或重大事件触发摘要任务；仅对新消息增量抽取。模型返回候选 JSON，代码核对实体、时间和原始消息，不接受凭空新增的承诺、金钱变化或 USER 决定。
- 使用规范化关键词与来源 ID 去重；同一事实相反时保留两个版本并标记待确认，不让模型自行选择“真相”。milestone 只能由显式确认或受控规则写入，不随衰减删除。
- 记忆更新异步执行、失败可重试，聊天发送不等待摘要。删除消息时使相关候选失效并重建投影；导入存档时按版本迁移和去重。

### 4.3 检索、遗忘与用户控制
- 每次检索先按世界/账号/角色/可见性过滤，再按词项相关度、重要度、可信度、时近性和关系线索排序；有 embedding 时仅作为附加分数。固定 token 预算，返回命中理由和来源以便调试。
- 低重要度记忆会降低检索权重，必要时合并为摘要；“突然想起”只从真实已知的旧记忆中抽样，设置冷却，不制造新事实。
- 可视化页支持查看来源、置顶、纠正、隐藏、删除与导出。删除当前身份记忆时同步清理 IndexedDB、摘要索引、缓存与调试快照，并验证其他身份不受影响。

### 4.4 验收
同一角色切换 USER 身份后检索结果隔离；错误摘要不会变成事实；纠正优先于旧记忆；无 embedding 可用；删除、导出、导入后的检索结果可复现。

## 5. 各 App / 玩法详细规格

> 每项包含：玩法 → 数据 → LLM 调用 → 验收要点。

### 5.1 聊天

**消息账本**：消息采用不可变 id、worldId、accountId、conversationId、senderId、type、payload、createdAt、deliveredAt、readAt、status、replyTo、revision、effect。按时间与稳定序号排序。允许类型由枚举和各自 schema 校验；未知类型显示“暂不支持的消息”占位，不丢失原始数据。正文与媒体分开存储，媒体只保存 ID 引用。

**发送状态机**：draft → queued → sent → delivered → read；失败进入 failed 并可重试。发送、通知、钱包操作使用同一个 idempotencyKey，刷新或重复点击不产生双份。离线消息先入队，恢复时按顺序处理。撤回写 tombstone，保留原文仅用于授权玩法和本机导出；编辑保留 revision；重新生成保留 branchId 与上一版本，切换分支不会覆盖其他消息。

**消息能力**：文本、表情包、图片、文字图、语音、位置、引用、合并转发、拍一拍、通话记录、红包/转账均采用独立 payload schema。资金由钱包状态机结算，聊天只显示凭据；表情 ID 必须属于当前角色可见的库。通话接听、已读与延迟回复由日程和设备状态决定，模型只写台词。

**表达效果**：回声是 text 消息的 effect，CHAR 和 USER 均可在消息菜单应用/重播；USER 也可从输入框“＋”中预选下一条。回声仅在前台播放，气泡副本铺开全屏、单字独立运动；保存的是 effect 标记而非动画帧。尊重减少动态效果设置。emoji reaction 仅显示单个 emoji，不再有包裹胶囊。

**心声**：入口藏在输入框“＋”的功能抽屉。只有 USER 主动打开后才显示心声卡，点“生成此刻心声”才调用模型；同一角色消息锚点只生成一次并按 worldId/accountId/conversationId 隔离缓存。蘑菇云思考气泡承载的是虚构文学独白，不是模型思维链；不自动发给 CHAR，也不自动写入事实记忆。

**LLM 边界**：chat_reply 可以返回消息文字及受控 action/effect；代码验证角色、余额、日程、表情 ID、长度和引用目标后才提交。wait 时间只作为建议，实际 dueAt 由调度器求可用时间。模型异常时保留 USER 消息，提供重试，不伪造已发送的 CHAR 回复。

**验收**：每种类型可存档/导出；回声对双方可播放且普通消息不触发；心声不自动生成、跨账号不可见；关闭页面后待发消息和资金状态不重复；非法 type、损坏媒体和模型无效 JSON 不会使会话崩溃。

### 5.2 通讯录 / 加好友 / 大小号

- 身份由 accountId 定义，头像、昵称、人设、好友、会话、动态、通知、记忆、心声和隐私设置都以它为作用域。切换身份只切换视图与密钥，不复制另一身份的已读、联系人或模型上下文。角色卡可以复用，关系与知识不能默认复用。
- 好友关系状态机：未认识 → 申请中 → 已接受/已拒绝/已过期 → 好友/已删除/已拉黑。申请包含 senderAccountId、receiverEntityId、验证文本、时间、来源及去重键；重复申请按冷却合并。代码根据角色边界、关系、日程和申请来源决定接受，模型只写拒绝或通过的措辞。
- 搜 ID、扫码导入、群内添加和推荐都指向同一实体解析器。二维码导入先做 schema 与重复 ID 校验；推荐必须有可解释的来源，不凭空暴露私人小号。
- CHAR 小号可绑定主实体但默认匿名；它的说话指纹只作为叙事线索。身份揭晓必须经过可见事件和代码条件，不能由提示词泄露内部绑定 ID。
- 联系人删除与拉黑不会物理删除共享角色卡；当前 accountId 下的关系、通知和会话索引更新。彻底删档需单独确认，避免影响其他账号的资料。
- 验收：多身份交替发送、搜索、接受好友、删除、拉黑和导出导入后数据不串号；重复申请无重复通知；角色忙碌时审批与消息时间线一致。

### 5.3 群聊
- 成员：user + 多个 char/NPC；群公告、@、群昵称、群红包（拼手气）、拉人 / 退群 / 禁言 / 建群。
- 生成：`group_reply` 一次输出多角色发言序列 `[{speaker, messages[]}]`；**发言人由代码按 availability 与关系权重抽选**，不在线的人不发言；角色之间会接话、吃醋、拆台。
- user 不在线时，由补算生成群聊记录（带时间戳）。
- **验收**：不会出现未在群里的人发言；发言顺序带延迟；补算的群聊时间线合理。

### 5.4 朋友圈 / 动态
- char/NPC 按日程发动态（文字 + 用户素材 / emoji 场景卡片）；点赞、评论、回复评论。
- user 发动态，可设可见范围（全部 / 分组 / 仅某人）；char 会评论，也可能「偷偷点赞又取消」。
- 共同好友互动可见（NPC 在 char 动态下评论，user 能看到）。
- **验收**：动态由日程与世界日志驱动，内容与近期事件一致。

### 5.5 论坛（三板块）
1. **短视频流**：垂直滑动 feed。视频由用户导入（本地文件 / 直链 URL / 图文卡片），AI 生成标题、评论区、达人 NPC；评论区有「NPC 网友」；char 也会刷并留言。
2. **匿名树洞**：每个账号随机匿名代号；NPC 与 char 小号发帖，user 可发帖；AI 生成回复；「猜猜是谁」玩法。
3. **X 式**：短文本、转发、话题、热搜（由世界事件生成）。
- 内容批量生成并缓存，下拉刷新才增量新增，控制成本。
- **验收**：无限下滑不卡；生成失败时用缓存兜底。

### 5.6 查手机（双向）
**A. user 查 char**
- 解锁：密码关卡，线索藏在剧情里（纪念日 / 生日等）；连续猜错，char 之后会说「有人动过我手机」。
- 内容模块：相册、备忘录、与 NPC 的聊天、浏览器历史、搜索记录、外卖 / 打车订单、user 的备注名（随好感度变化）、**未发送的草稿（输入了又删掉的话）**、闹钟、步数、账单。
- 来源：全部由日程 + world_log 生成，**首次打开时生成并缓存**，之后增量更新，保证不与既往矛盾。

**B. char 查 user**
- 由关系事件触发；查看的是 user「手机」里的内容（user 自填 / 自动记录的虚拟数据）。
- char 的反应由 LLM 写：吃醋 / 感动 / 装作没看见，并影响 affinity。
- 双向都有「被发现」机制与后果。

**验收**：同一 char 多次查看内容一致；新事件发生后手机内容有对应新增。

### 5.7 信箱（邮局）
把三个东西整合成一个 App 的三个 tab，共用一个**延迟投递队列**：
- **信件**（1 对 1 深度）：写信 → 投递延迟（2 小时～2 天，由「距离 / 日程」决定）→ 回信。信纸、邮票、封蜡主题；永久存档在信匣；可附照片 / 干花。
- **时间胶囊**：写给未来某日；到期时 char 或 user 拆封；char 也会主动写「未来信」。
- **提问箱**（已实现）：作为 tab 接入。
- **漂流瓶**（可后置）：只在「陌生人 / NPC」层面，随机、轻量、惊喜；和信件区分开：信件 = 深度，漂流瓶 = 随机小惊喜。
- **验收**：延迟投递在关闭页面再打开后仍按时送达；信件可导出。

### 5.8 角色日记
- char 每天（在日程结束后）生成一篇日记，**站在 char 视角写他对 user 的真实看法**；好感度 / 关系阶段达到门槛才能解锁阅读。
- 日记与「嘴上说的」可有差距（傲娇、口是心非），形成反差。
- 内容读取当日日程、world_log、对话摘要；写入 episodic 记忆。

### 5.9 梦境
- 每天早上 char 可分享昨晚的梦；梦由近期事件 + 潜在情绪（mood）+ 随机意象混合生成。
- user 也可记录自己的梦，char 会「解梦」。

### 5.10 情侣 / 关系空间
共享相册、共同账本（含 AA / 亲密付）、100 件事清单、异地双时钟、纪念日倒计时、共同歌单、专属头像框与聊天气泡（随亲密度解锁）。

### 5.11 小屋 / 生活模拟（动森 / 人生）
**不需要 3D 建模。** 采用 2D 俯视 tilemap（Canvas 或 DOM 网格）。素材：默认 emoji / SVG 占位；提供贴图包 / spritesheet 导入的 JSON 规范。
- **系统**：种植（作物生长阶段**用真实时间戳计算，离线也生长**）、家具摆放（网格 + 旋转）、采集 / 钓鱼 / 捉虫（真实时间刷新表）、商店与货币、季节天气（跟随现实）、NPC 邻居来访。
- **放置玩法**：离线结算收益；char 按日程在小屋里「生活」（出现在不同位置、做不同动作：浇水、看书、睡觉）；user 不在线时 char 会布置家具、种花，回来能看到变化。
- **剧情**：事件池 + 触发条件 + 分支，由**代码状态机**驱动；LLM 只负责台词与描写。事件结构 `{id, trigger, nodes[], effects[]}`。LLM 可以生成候选新事件，但必须通过 schema 校验才进入事件池。
- **数据模型**：`Plot{id,crop,plantedAt,stage}`、`Furniture{id,type,x,y,rot}`、`Inventory`、`Villager{...}`。
- **分期**：v1 = 摆放 + 种田 + char 出现；v2 = 钓鱼 / 采集 / 商店；v3 = 剧情事件与邻居。
- **验收**：关闭页面 8 小时后再开，作物阶段正确；char 位置与日程一致。

### 5.12 小游戏
共同原则：**规则全部由代码实现，LLM 只做角色发言 / 主持文案，不参与规则判定。**
- **狼人杀**：AI 玩家发言由 LLM 生成；投票、技能、胜负由代码判定；**每个 AI 玩家只拿到它该知道的信息**（隐藏信息隔离）；user 可当任意身份。
- **海龟汤**：内置题库 JSON（汤面 / 汤底）+ LLM 主持；主持回答**强制枚举**「是 / 否 / 无关 / 接近了」；汤底只出现在主持 prompt 里，防止提前泄露；可让 char 作为队友一起猜。
- **大富翁 / 飞行棋**：完整规则代码实现；LLM 只负责角色间的「嘴炮」与反应；支持 user + 多个 char 同桌。
- **验收**：各游戏可完整跑通一局；LLM 输出异常不会破坏游戏状态。

### 5.13 文字游戏（VN，带立绘）
- 剧本 JSON：场景、背景、立绘（用户导入，支持表情差分）、对话、选项、变量 / flag、结局。
- **AI 即兴模式**：给出大纲 + 角色，LLM 每一幕输出 `{narration, dialogue[{who,text,emotion}], choices[]}`；代码保存 flag；立绘表情由 `emotion` 映射。
- 功能：存档 / 读档、回想、自动 / 快进、CG 收集、多结局图鉴。

### 5.14 陪伴：一起看 / 听 / 读 + 番茄钟
- **一起看**：导入本地视频 / 直链；暂停 / 进度同步；char 在特定时间点弹出「弹幕式短评」。生成策略三选一：用户提供字幕 / 简介；定时截帧（需视觉模型）；仅根据片名与进度。
- **一起听**：本地音频 + .lrc 歌词；char 在歌词 / 间奏处发表感想。
- **一起读**：导入 txt / epub；char 在段落旁「划线 + 批注」。
- **番茄钟**：专注 / 休息计时；char 陪伴（安静模式，偶尔一句鼓励）；完成得小屋货币；专注期间 char 的日程同步为「学习 / 工作」，两人各忙各的。

### 5.15 现实桥 / MCP
- **现实桥**（全部可选、需授权）：真实时间 / 时区、天气（用户自填 API 或 open-meteo）、城市（手填或授权）、电量（Battery API）、深色模式、日历（用户导入 .ics）。**绝不读取剪贴板 / 通讯录。**
- **MCP**：浏览器端仅支持远程 HTTP/SSE MCP。实现 MCP 客户端：工具列表、调用、结果展示。工具调用**必须用户确认**，并显示安全提示。LLM 通过 function calling 调用。

### 5.16 线下模式（约会 / 共同经历）

**定位**：线下模式不是「另一种聊天」，而是**一起经历一件事**：有地点、有时间条、有回合、有隐形数值，结束后与线上互通。
**分期**：v1 = 5.16.1–5.16.7 + 5.16.10（地点包、回合数值、心声、结算联动）；v2 = 5.16.8–5.16.9（小互动、礼物）；v3 = 5.16.11（长线模式）。

#### 5.16.1 会话（Session）
- **进入方式**：线上发起约会邀约（char 是否答应由代码按日程 availability + affinity + 随机数判定，LLM 只写回应文案）；日程里的约定到点；手动点「线下」入口；剧情事件触发。
- **生命周期**：prepare → in-scene → wrap-up → 回到线上。
- **数据**：`Session {id, type(date|trip|home|adventure), locationId, startAt, timeBudget, participants[], stats{distance,mood,tension}, prep{}, attention[], flags{}, log[], endedAt, status(active|paused|ended|interrupted)}`。
- 中途退出自动存档，可「继续约会」；超过 24 小时未继续则自动结算为 `interrupted`，char 之后的线上表现相应变化。

#### 5.16.2 出门前准备
- user 可选：穿搭、出发时间、随手礼物；结果存入 `session.prep`，影响开场 stats 与 char 开场反应。
- char 可能迟到或临时爽约（概率由代码算，受日程与性格影响），LLM 写迟到时的说辞。

#### 5.16.3 地点包（Location Pack）
JSON 结构：
```json
{
  "id": "cafe_01", "name": "街角咖啡馆", "tags": ["quiet","indoor"],
  "ambience": "安静，有咖啡香，靠窗座位阳光很好",
  "variants": {"timeOfDay": ["morning","afternoon","night"], "weather": ["sunny","rain"]},
  "objects": [{"id":"window","name":"窗外","interactions":[{"id":"look","cost":1,"unlock":null}]}],
  "eventPool": ["spill_coffee","meet_acquaintance"],
  "npcs": ["barista"]
}
```
- 内置 6–8 个模板：咖啡馆、书店、游乐园、海边、夜市、电影院、公园、家里。
- 支持用户导入自定义地点包；世界书可向地点注入额外设定。
- BGM / 环境音字段为可选 URL，**由用户自备**，项目不内置。

#### 5.16.4 场景卡与可互动物件
- 顶部固定场景卡：地点 / 时间 / 天气 / 在场人物 / 剩余时间条。
- 下方是物件 chips（桌上的杯子、窗外、路边的猫……）。点击后：代码检查条件（是否已用、是否解锁、时间成本）→ 调用 LLM 写一小段描写 → 可能触发事件 → 改变 stats。
- **注意力记忆**：记录 user 点过、停留超过 3 秒的物件到 `session.attention[]`，char 的反应会引用它。

#### 5.16.5 回合与隐形数值
- **三条数值（0–100，代码维护，UI 默认隐藏）**：`distance` 距离感、`mood` 氛围、`tension` 紧张度。
- 每轮：user 点 3 个倾向选项之一（每个带 `tag`），或自由输入。
  - 点选项：`tag` 直接进入规则表。
  - 自由输入：由同一次 LLM 调用回传 `detected_action`（枚举），代码校验后更新 stats，**延迟一拍生效**（省一次调用）。
- **规则表**（JSON 可配置）：`action_tag × 地点 × 天气 × char 性格标签 → stats 变化量`。
- **行动枚举**：`approach, retreat, silence, joke, tease, comfort, gift, touch, ask, confess, observe`。
- **时间条**：每轮按行动消耗时间，归零触发 wrap-up；剩余时间少时，prompt 注入「快要分别」的语气提示。
- **阈值事件**：`distance` 低于阈值触发「靠近」事件，`tension` 高触发「沉默 / 心跳」事件，`mood` 低触发「冷场补救」事件。事件结构 `{id, when{stats,location,flags}, weight, once, effects, textHints}`。

#### 5.16.6 输出协议（offline_turn）
```json
{
  "narration": "……",
  "dialogue": [{"who": "char", "text": "……", "emotion": "shy"}],
  "inner_os": "……",
  "choices": [
    {"tag": "approach", "text": "……"},
    {"tag": "silence",  "text": "……"},
    {"tag": "joke",     "text": "……"}
  ],
  "detected_action": "joke",
  "event_request": null
}
```
**校验**：`choices` 必须 3 条且 tag 属于枚举；`emotion` 属于枚举；`narration` / `dialogue` 里**不得出现 user 的行动、台词或想法**（检测 user 名作主语的动作描写、以 user 身份说出的引号台词）；长度在设置区间内。失败则带错误信息重试，最多 2 次，再降级为纯 narration + dialogue。

#### 5.16.7 心声旁白（inner_os）
- 开关项；好感度 / 关系阶段达到门槛才解锁。
- UI：浅色斜体小气泡，与嘴上说的形成对照（傲娇、口是心非）。prompt 要求「真实想法可以与说出口的不同」。
- 写入 char 自己的记忆；不进入 user 可见的 world_log。

#### 5.16.8 小互动（mini-interactions）
**规则由代码实现，不靠 LLM 判定。** 每个小互动是独立模块，接口：`start(session) → {statsDelta, flags, memoryHint}`。
- **拍立得合影**：Canvas 合成（背景 + 立绘 / 头像 + 边框 + 日期），自动存入相册。
- **牵手**：长按 / 节奏点击，成功率影响 distance。
- **共伞**：拖动保持相对位置，越近 distance 越低。
- **摩天轮告白**：时机条，判定成功 / 失败 / 差一点。
- **逛店买礼物**：商品列表，浏览行为写入 `attention[]`。

#### 5.16.9 礼物与惊喜
`attention[]` 中的物件在 wrap-up 时由 char 决定是否「记住」；之后在生日 / 纪念日事件中，char 通过 `commitments` 写入日程，惊喜送出对应礼物。

#### 5.16.10 结算与线上联动（wrap-up）
- **触发**：时间条归零 / user 点结束 / 事件强制结束。
- **一次 `offline_summarize` 调用**，输出：
```json
{
  "summary": "……", "highlights": ["……"], "mood_after": "happy",
  "milestones": ["第一次牵手"], "memory_entries": [{"text":"……","importance":0.8}],
  "unsaid": ["其实今天想说……"]
}
```
- **写入**：episodic / milestone 记忆、world_log、日程回写（回家时间）、生成**约会回顾卡片**（拍立得 + 三句话 + 数值曲线，可分享）。
- **线上联动**：
  - 回家后 30–120 分钟内（落在 availability 高的时间点），char 主动发消息回味，带着当天的具体细节。
  - `unsaid[]` 里没说出口的话，夜间以「线上补话」形式发送（受 affinity 门槛影响）。

#### 5.16.11 长线模式（v3）
- **旅行**：多个 session 串成一条链；user 选点，代码生成行程时间轴；每日突发事件；联动信箱寄明信片、联动日记（5.8）写旅行日记。
- **同居日常**：无固定地点，按日程生成「晨 / 午 / 晚」片段场景（做饭、雨天、生病照顾），背景取自小屋（5.11）。
- **冒险 / 探案**：世界书驱动的任务型 session，线索存在 `flags`，char 作为搭档有自己的推理与盲区。

#### 5.16.12 排版与沉浸
- 动作（斜体）/ 对话（引号高亮）/ 旁白（灰色）/ 心声（浅色气泡）分色；场景标题卡淡入；逐段显示，可点击跳过。
- 时间、天气可跟随现实（现实桥）或手动设定。
- **设置项**：视角（第二 / 第三人称）、文风（轻小说 / 文艺 / 日常口语）、每轮字数区间、心声开关、选项开关、「沉浸模式」（隐藏数值与选项 UI，只留自由输入）。

#### 5.16.13 稳定性硬约束（写入 A 层协议）
1. **不得替 user 行动、说话或思考。**
2. 数值、事件、时间、结局由代码管理；LLM **不得自行宣布「约会结束」或修改数值**，只能通过 `event_request` 提请，是否批准由代码决定。
3. 每轮开头注入 session 状态摘要（地点、剩余时间、stats、flags、最近 3 轮摘要），防止长篇偏离。
4. 每 N 轮做滚动摘要，控制上下文长度。
5. 弱档模型：关闭 `inner_os`，`choices` 由代码模板生成，LLM 只写 narration + dialogue。

#### 5.16.14 验收
- 完整走一次「准备 → 3 个地点物件互动 → 阈值事件触发 → 时间条归零 → 结算」不崩溃。
- 数值只会被代码规则修改；LLM 输出里试图宣布结束或改数值时被拒绝。
- 校验能拦住「替 user 说话」的输出并重试。
- 结算后 char 在线上主动发出带当天细节的消息；约会回顾卡片可生成并导出。
- 中途关闭页面再打开可继续；超过 24 小时自动结算为 `interrupted`。

### 5.17 预设 / 世界书 / 美化

- 预设按协议层 A–H 编排，只允许编辑 B–D 与表达偏好；A、H 的 schema 和安全边界固定。模块保存 id、版本、位置、开关、token 上限和来源；导入时校验版本与占位变量，提供预览差异和撤销。
- 世界书条目保存 keys、content、priority、position、group、probability、constant、scope、tokenCost。先按世界/角色/账号过滤，再关键词触发和有限递归；概率使用稳定 seed，禁止每次重渲染随机跳变。冲突按优先级与 token 预算裁剪并在调试面板给出命中理由。
- 主题把设计 token（颜色、字体、圆角、密度）、图标包、壁纸、气泡、桌面布局与自定义 CSS 分开存档。主题导入先校验 schema、文件大小、媒体类型与 URL；不执行导入包中的 JS/HTML。CSS 只作用于限定容器，过滤 @import、url(javascript:)、全局覆盖与危险选择器，保留一键恢复默认。
- 验收：恶意预设不能覆盖协议层；世界书触发可复现；主题损坏可回退；换主题不修改消息数据、记忆或世界状态。

### 5.18 手机拟真细节

- DeviceState 是独立状态机：locked、airplaneMode、doNotDisturb、lowPower、batteryLevel、networkStatus、signalQuality。状态变化写事件时间戳并由通知、通话、聊天投递共同读取；显示层不能单独伪造“消息未达”。
- 飞行模式暂停传输与来电，但世界事件照常发生；退出后按原 dueAt 顺序投递。勿扰只静音/折叠通知，不改变已读或发送成功。低电量节省动画与后台补算；“没电关机”仅在用户选择模拟电池模式时触发，真实 Battery API 不可用时不冒充真实电量。
- 锁屏、通知中心、控制中心和角标共用通知账本，通知拥有 accountId、sourceId、occurredAt、deliveredAt、readAt 和 collapseKey。点开后跳到正确账号与会话；同一事件不能出现多个角标。隐私模式在锁屏隐藏正文。
- 桌面小组件读取世界与设备状态的只读投影；应用商店以“解锁模块/显示入口”为状态，不下载可执行代码。每个模块有 disabled、installed、unlocked 三种显式状态。
- 验收：飞行模式/勿扰/锁屏切换后的通知与聊天状态一致；重启后状态恢复；跨账号通知不泄露；无电池或网络 API 时使用清楚标注的模拟状态。

## 6. 额外创意（可选，按性价比排序）

1. **回忆录 / 年度报告**：自动整理「我们一起度过的日子」，生成可分享的长图 / 名片（最有传播效果）。
2. **情绪天气**：char 头像旁显示今日心情图标，点开有一句「为什么」。
3. **秘密档案**：char 有自己的目标和秘密，关系推进逐步解锁。
4. **旅行系统**：char 与 user 各自旅行，互寄明信片（地点 + 占位图 + 手写体）。
5. **周期仪式**：早安晚安、打卡、纪念日提醒，可自定义。
6. **悄悄话模式**：夜间低光界面，char 语气变轻，消息不推送。
7. **节日副本**：季节 / 节日限时事件与小屋装饰。
8. **多世界线**：关键选择可回溯存档，比较不同结局。
9. **彩蛋触发词**：隐藏对话触发稀有事件卡，可收集。
10. **共同宠物**：在小屋里养，宠物状态影响 char 日程与话题。
11. **剧本杀 / 跑团模式**：AI 当 DM，char 是队友。
12. **NPC 生活可被撞见**：论坛里遇到 char 的同事 / 朋友，对上「梗」。

## 7. 通用工程要求

- **存储与迁移**：IndexedDB 保存世界、消息、记忆、任务、媒体和存档槽位；localStorage 只保存轻量 UI 偏好与当前槽位 ID。现有 localStorage 数据按版本迁移到 IndexedDB，先双读校验与可回滚备份，确认一致后再清理旧键。事务提交后才更新 UI；每张表有主键、accountId/worldId 索引与 schemaVersion。
- **导入导出**：多槽位独立；导出包含 manifest、版本、校验和、JSON 数据及媒体清单。导入先解析到临时槽、验证引用/大小/类型，成功后原子切换；失败不覆盖当前档。提供手动备份及适度的本机备份提醒，不上传用户 Key。
- **性能**：消息和动态按游标分页；长列表虚拟滚动；图片入库前压缩与尺寸限制；大摘要放 Worker/空闲时段。375–430px 优先，控制首屏脚本量和离线缓存上限。
- **安全与隐私**：API Key 只在本机保存，导出默认排除；可选口令加密须使用标准 Web Crypto。导入文件按 schema 白名单校验；所有用户/模型文字作为文本渲染；CSS 限定作用域并可恢复；外部 URL 限制协议。模型上下文只含当前账号、当前世界和角色可知事实。
- **工程分层**：UI 通过用例/命令调用 Store、WorldEngine、MemoryService 和 LLM Gateway；事件总线只传领域事件，不直接写 DOM。所有外部模型输出经过解析、schema、业务权限及幂等校验，失败可重试、可追踪、可降级。
- **体验与可访问性**：文案集中 i18n；交互可键盘操作，有清楚标签与焦点；动画支持 prefers-reduced-motion；读屏可获知发送/失败/投递状态。首次使用说明 AI 内容、用户素材授权与本地数据保存方式。
- **可观测性与测试**：调试记录任务、prompt 版本、耗时、重试与校验原因，脱敏后可导出。纯规则模块用固定时钟/seed 测试，覆盖跨午夜、离线重放、身份隔离、冲突记忆、资金幂等和存档往返；浏览器回归覆盖聊天效果、心声按需生成和离线启动。

## 8. 开发路线图
- **Phase 0 地基**：Store、EventBus、导入导出、LLM 网关（含校验 / 重试 / 调试面板）、主题基础。
- **Phase 1 MVP**：聊天（全消息类型）+ 日程 + 记忆 + 预设 / 世界书 / 美化。
- **Phase 2 社交世界**：世界引擎（补算 + 关系图）、通讯录 / 大小号、群聊、动态、查手机。
- **Phase 3 情感内容**：信箱、日记、梦境、情侣空间、论坛、一起看听读、番茄钟。
- **Phase 4 玩法**：小游戏（海龟汤 → 狼人杀 → 大富翁 / 飞行棋）、小屋 v1–v2。
- **Phase 5 扩展**：VN、现实桥、MCP、线下模式、小屋 v3、分享卡片与年度报告。
- **Phase 6 打磨**：性能、彩蛋、新手引导、模板包。
